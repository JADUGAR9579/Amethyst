# Code Mode — First Milestone Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove the end-to-end flow: Amethyst spawns OpenCode, creates a session, fetches real agents/models, sends a prompt, receives streaming events, renders tool calls with approval, and shows results — all through OpenCode's real API.

**Architecture:** Amethyst backend spawns `opencode web` as a managed subprocess and reverse-proxies all `/api/opencode/*` requests to it. Amethyst frontend has a thin JS client (`opencode.js`) wrapping `fetch`/`EventSource` against the proxy, and a native React view (`Code.jsx`) that renders sessions, messages, tool calls, and permissions using data from OpenCode's API. OpenCode is the sole source of truth.

**Tech Stack:** Python/FastAPI (backend proxy + process manager), httpx (async proxy), React/JSX (frontend view), EventSource (SSE streaming)

**Spec:** [code-mode-design.md](file:///home/wayne/.gemini/antigravity-ide/brain/f2c8b8b0-7961-4fa2-80a0-88a3395f0f0e/code-mode-design.md)

## Global Constraints

- OpenCode binary: `/home/wayne/.opencode/bin/opencode` (or `which opencode`)
- OpenCode spawned with `opencode web --port <PORT> --hostname 127.0.0.1 --cors http://localhost:5173`
- Proxy prefix: `/api/opencode/` strips prefix and forwards to `http://127.0.0.1:<PORT>/api/`
- SSE passthrough must not buffer — `StreamingResponse` with no content-length
- No duplication of OpenCode data structures — types are inferred from API responses
- Follow existing Amethyst patterns: `APIRouter` for backend, lazy-loaded views for frontend, `nav.js` entry for navigation

## Review Focus

1. **SSE connection drops** — browser navigating away from Code view must close EventSource; reconnect on return without duplicate events
2. **OpenCode process crash** — backend must detect exit, report status, allow restart; frontend must show connection-lost state
3. **Concurrent sessions** — switching sessions must update SSE filter; events from wrong session must not pollute current view
4. **Proxy timeout on streaming** — long-running tool calls may take minutes; proxy must not timeout SSE or POST /prompt responses
5. **Permission timeout** — if user ignores approval, OpenCode may timeout; frontend should show expiry gracefully

```python
async def proxy(request: Request, path: str):
    """Reverse proxy to opencode. SSE-aware: if Accept includes text/event-stream,

    ...
```

Proxy implementation:
- Build target URL: `http://127.0.0.1:{port}/api/{path}?{query}`
- Forward headers (except Host)
- For SSE (Accept: text/event-stream): use `httpx.AsyncClient.stream()` and yield chunks via `StreamingResponse`
- For regular requests: forward body, return response with same status/headers
- On connection error: return 502 with status info

- [x] **Step 3: Implement SSE event routing in `Code.jsx`**

`handleEvent(event)` maps OpenCode event types to React state updates:
- `session.next.prompted` → add user message
- `session.next.step.started` → set streaming=true, add assistant message placeholder
- `session.next.text.started/ended` → accumulate/finalize text
- `session.next.tool.called` → add tool call block
- `session.next.tool.success/failed` → update tool result
- `session.next.step.ended/failed` → set streaming=false
- `permission.v2.asked` → show approval UI
- `permission.v2.replied` → dismiss approval UI
- `session.next.reasoning.started/ended` → toggle thinking indicator
- `session.next.context.updated` → update token display

Text deltas: OpenCode sends raw SSE data lines between text.started and text.ended boundaries — append each to a buffer and update the last message part.

- [x] **Step 4: Implement permission approval UI**

When `permission.v2.asked` event fires, render a modal/banner with:
- Tool name, action description, file patterns
- "Allow" → `opencode.replyPermission(sessionID, requestID, { reply: 'allow' })`
- "Deny" → `opencode.replyPermission(sessionID, requestID, { reply: 'deny' })`
- "Allow always" → `opencode.replyPermission(sessionID, requestID, { reply: 'always' })`

- [x] **Step 5: Implement model/agent picker**

Dropdowns populated from `opencode.listModels()` and `opencode.listAgents()`. Group models by provider. Show current selection from session data. Selecting calls `opencode.switchModel()` or `opencode.switchAgent()`.
